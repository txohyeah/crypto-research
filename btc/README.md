# BTC Analysis — BTC 筑底与见顶信号监控系统

基于链上估值指标、市场情绪与资金流的 BTC 周期位置监控系统。每日自动采集数据 → 判定引擎打分 → 生成 HTML/Markdown 报告 → 飞书推送。

包含两套**互为镜像**的决策清单：

---

## 🔻 筑底系统（六信号清单）

定位：熊转牛的**建仓决策系统**。六项信号 ≥3 项达标时触发建仓提醒。

| # | 信号 | 判定口径 |
|---|------|---------|
| 1 | MVRV Ratio | 1.0–1.2（价格跌回全网平均持币成本区） |
| 2 | 恐惧贪婪指数 | < 15 极度恐慌 |
| 3 | ETF 资金流 | 近 20 日 ≥ 14 天净流入 |
| 4 | 现货需求 | funding 30 日累计净需求 > 0 且 7 日均值 > 0 |
| 5 | 二次探底 | 价格回踩动态前低上方观察区且缩量守住（事件触发型） |
| 6 | 时间窗口 | 顶部后 ~12 个月的历史筑底窗口 |

关键工程设计：
- **动态支撑**：`detect_swing_low_support()` 自动锚定摆动低点（swing K=5、反弹 ≥15% 显著性过滤），拒绝硬编码支撑位
- **缩量判定**：回踩腿 vs 上涨腿成交量对比，恐慌放量与缩量企稳分级
- **诚实降级**：数据缺失天数过多时该信号标 ⏳ 待验证，不虚报达标

## 🔺 见顶系统 v2（六维三态）

定位：牛转熊的**离场决策系统**。每个维度每日输出 🟢正常 / ⚠️过热 / 🔴转折 三态读数。

| 维度 | 核心指标 | 🔴 转折条件 |
|------|---------|------------|
| 估值 | MVRV Z-Score | 从峰值回落 ≥35% |
| 情绪 | NUPL + 恐惧贪婪 | NUPL 跌回 <0.65 或 FG 自峰值暴跌 ≥25 点 |
| 获利了结 | SOPR + 已实现利润 | SOPR 连续 N 日 <1.0（全网花费转亏） |
| 机构资金 | ETF 净流入 | 连续净流出且累计破阈值 |
| 杠杆结构 | funding + OI | 爆仓潮或 OI 高位骤降 >15% |
| 筹码派发 | reserve risk + 已实现利润 | 单日已实现利润超阈值 |

**两级触发规则**（唯一行动出口）：
```
⚠️ 过热 ≥ 2 维                           → 进入顶部区域，停止加仓
🔴 转折 ≥ 2 维 且含资金流/杠杆类硬信号      → 顶部确认，执行离场
```

为什么顶部用 Z-Score 而底部用 Ratio：MVRV Ratio 的顶部阈值逐轮递减（4.0→3.4→2.4），静态阈值必失效；Z-Score 归一化后历史双顶稳定落在 7–9 区间，跨周期可比。详见 `docs/BTC见顶信号说明.md`。

## ⏱️ 减半周期钟

实证四轮周期的「减半 → 终顶」天数：367 / 526 / 338+548 / **534**，近三轮收敛于 **530 ± 15 天**。

可操作口径：减半后第 ~500 天进入高危区、~555 天解除风险。周期钟随每日报告自动输出当前状态与下轮高危窗口。

## 📁 目录结构

```
├── scripts/              # 全部代码
│   ├── btc_monitor_db.py     # SQLite 存储 + 筑底/见顶判定引擎 + 周期钟
│   ├── btc_collector.py      # 数据采集（多数据源，限流熔断）
│   ├── btc_daily_collect.py  # 每日流程编排（cron 入口）
│   ├── btc_report_html.py    # HTML 报告生成
│   ├── btc_*_chart.py        # 各指标趋势图
│   └── feishu_send_*.py      # 飞书推送
├── templates/            # Jinja2 报告模板（数据与展示分离）
├── docs/                 # 方法论文档
└── reports/              # (gitignore) 每日生成的报告
```

## 📡 数据源

| 数据 | 来源 |
|------|------|
| MVRV-Z / SOPR / NUPL / Puell / reserve risk / realized profit | bitcoin-data.com |
| 恐惧贪婪指数 | alternative.me |
| 价格 / 现货量 / funding / OI | Binance API |
| ETF 资金流 | CoinMarketCap |

免费档限流保护：请求间隔 8s、遇 HTTP 429 立即熔断中止、增量续传。

## ⚙️ 配置

飞书推送相关配置**环境变量优先**，未设置时回退读取 `~/.qwenpaw/config.json` 的 `channels.feishu` 字段：

| 环境变量 | 说明 |
|---------|------|
| `FEISHU_APP_ID` | 飞书自建应用 App ID |
| `FEISHU_APP_SECRET` | 飞书自建应用 App Secret |
| `FEISHU_OPEN_ID` | 报告接收人 Open ID（也可通过 `--user` 参数指定） |

信号策略参数（MVRV-Z 警戒线、SOPR 转折天数、摆动低点检测参数等）全部常量化在 `scripts/btc_monitor_db.py` 文件头——它们是系统方法论的组成部分，随版本管理，不走环境变量。
